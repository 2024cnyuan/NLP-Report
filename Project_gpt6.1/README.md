# TensorScope｜NLP 原理实验室

六个可操作的NLP中阶实验：词向量、序列模型、Text-CNN、注意力、多模型对照、损失与优化。计算在本地完成，没有后端、在线模型或API Key。

## 离线演示

在Windows双击 [release/index.html](release/index.html)。保持同目录的app.js和style.css完整；不需要启动Vite或安装Node。可以整体复制release文件夹到中文或空格路径。

已在WSL Chromium验证真实file://、Blob Worker和核心交互；Windows Chrome/Edge仍需人工验收，不冒充已经测试。

## 项目使用说明

### 1. 打开项目与基本操作

直接打开 `release/index.html` 即可使用。`index.html`、`app.js`、`style.css` 必须保持在同一个目录，复制或分发时请整体复制 `release/`。

演示不需要 Node、Vite、账号、API Key 或网络。数据解析、训练、预测和导出都在本地完成，不会上传输入文件。

左侧导航包含六个实验模块，以及“数据集管理”“实验笔记”“使用说明”。推荐第一次使用按以下顺序操作：

1. 进入“注意力机制”，使用默认样例观察结果。
2. 点击热力图中的一个数字，查看右侧计算检查器。
3. 点击“固定为 A”，改变一个参数，再运行一次。
4. 对比 A/B 结果，然后“保存实验”或“导出”。
5. 熟悉操作后，再尝试自己的语料和分类数据。

多数实验页面打开时会自动计算默认样例或展示已有结果。修改输入、参数后，需要再次点击对应的计算或训练按钮；旧结果会标为过期，不能直接保存为当前配置的结果。

### 2. 原理模式、实验模式与自动化测试

界面上的名称是“原理模式”和“实验模式”，不是“测试模式”。另外，开发目录里的自动化测试是验证软件是否正确的工具，与网页里的实验操作不同。

| 部分 | 用途 | 推荐操作 |
|---|---|---|
| 原理模式 | 理解一个结果是怎样逐步算出来的 | 使用短文本、低维向量，检查公式、输入和中间状态 |
| 实验模式 | 改变输入和参数，观察实际结果与模型差异 | 训练、批量评测、A/B 对照、筛选错误样本 |
| 自动化测试 | 检查算法和网页是否正确，防止修改引入错误 | 开发时运行 Vitest 和 Playwright |

当前版本中，原理/实验切换主要用于标记工作模式、提示使用方式，并记录到保存的笔记中。它不会自动改变参数、切换权重或重新运行计算；Worker、分块展示和逐项检查由具体模块提供，不是只有某一种模式才能使用。

右上角的播放图标是“演示视图”：放大主要画布、收起部分界面，适合投屏讲解。它不是录制动画，仍然可以操作和计算。

### 3. 通用功能：计算检查器、A/B 对照和任务控制

#### 计算检查器

点击支持检查的热力格子、隐状态、卷积激活、池化值或损失点，可以在右侧看到：

- 当前数值及对应公式。
- 实际参与计算的输入、权重或中间值。
- 张量形状、模型标识和上游来源。

“锁定此计算”可以保留当前检查内容，方便继续观察图形；要检查其他数字，先解除锁定。

#### A/B 对照

先运行一次，然后点击“固定为 A”。接着修改一个因素并重新运行，当前结果就是 B。

例如，保持语料和随机种子不变，只调整词向量窗口；或者保持注意力输入不变，只屏蔽一条连接。页面会提示配置差异，并在兼容时展示差值或叠加曲线。

不同维度、词表或序列长度不一定能直接相减。词向量的二维图是投影，也不能只凭图上距离判断原始向量是否更接近。对照说明的是当前模型内部的变化，不证明现实因果关系。

#### 暂停、继续和取消

后台计算期间会显示任务状态与进度，可以暂停、继续或取消。暂停保留的是当前页面会话中的计算状态，不是可在关闭浏览器后继续训练的磁盘检查点。

### 4. 六个实验模块

#### 01｜词向量空间

用于观察词语如何从上下文中学习向量，以及训练参数怎样影响邻居关系。

输入每行一句的语料，选择分词方式和算法，再设置窗口、维度、训练轮数、学习率及随机种子，点击“训练词向量”。

三种算法的区别：

- Skip-gram：用中心词预测上下文。
- CBOW：用上下文表示预测中心词。
- GloVe：根据词语共现统计学习向量。

训练后可以定位词语、查询最近邻、进行 `b − a + c` 类比检索、筛选词频，以及检查最后一次实际参数更新。散点图支持拖拽平移、滚轮缩放和 Shift 框选。

最近邻和类比在原始向量空间计算，PCA 二维图只用于观察。小语料不保证得到符合常识的语义类比。

“使用已导入数据”会从数据集管理读取语料；有标签样本使用训练划分，无标签样本可作为语料。“送入 RNN / CNN”会把向量快照送到多模型工作台，用于后续神经模型初始化。

#### 02｜序列与记忆

用于理解 RNN、LSTM、GRU 如何沿时间处理 Token，以及最终损失如何向前面的状态传播梯度。

选择教学初始化或已训练模型，输入序列后点击“计算完整轨迹”。可以前进一步、回退一步、自动播放、重置到初始状态，也可以直接点击某个 Token。

页面展示隐藏状态；LSTM 还展示细胞状态，LSTM/GRU 展示对应门控。梯度图来自最终分类交叉熵的真实反向传播，不是人为绘制的趋势。

“长序列梯度案例”用于观察早期状态的梯度变化。播放和回退只是浏览已计算轨迹，不会重新训练权重。

教学初始化用于讲解结构，不代表训练好的分类器。来自多模型工作台的解释则保留原模型和原 Token。当前固定四模型对照只包含 RNN；LSTM/GRU 在本页学习，不会被当作 RNN 送入对照。

#### 03｜文本卷积

用于追踪 Text-CNN 的完整分类过程：

```text
文本 → Embedding → 多窗口卷积 → ReLU → 最大池化 → 分类输出
```

输入文本并选择模型来源，点击“计算卷积与分类”。可以选择卷积核、移动窗口、检查逐项乘加。

点击池化值，会定位到产生最大值的原始窗口，帮助理解“模型选中了哪一段局部特征”。

还可以显式修改当前卷积核的一个权重，再重新计算。修改会生成新模型版本；需要重新评测，不能继续沿用修改前的成绩。

#### 04｜注意力机制

用于理解 Query、Key、Value 怎样产生注意力权重和加权输出。

源序列对应 Key/Value，目标序列对应 Query。输入使用空格预分词，可以选择普通点积、缩放点积或加性打分，然后点击“计算注意力”。

热力图每一行表示一个 Query 对全部 Key 的权重分布。点击格子可检查向量、打分、Softmax 和行概率和；点击输出值可检查 Value 的逐项加权求和。

“编辑掩码”允许点击格子屏蔽或恢复连接。屏蔽后该行重新归一化，整行全部屏蔽会拒绝计算。高级操作可以直接输入 Q/K/V 矩阵 JSON。

默认向量是固定教学映射，不是翻译模型学习出的表示；热力图不能作为真实翻译对齐结果。

#### 05｜多模型对照

用于在同一批样本上比较 NB、SVM、RNN 和 Text-CNN，并进一步追踪错误原因。

主要操作有两个：

- “四模型批量评测”：使用现有权重进行预测，不重新训练。
- “训练四模型并评测”：使用当前数据和参数重新训练，再评测固定测试划分。

输入一段自己的文本并点击“并排预测”，可以查看四个模型的预测、分数及 OOV 数量。OOV 指输入中不在模型词表里的 Token。

批量结果包含 Accuracy、Precision、Recall、F1、Macro-F1 和混淆矩阵。可以筛选错误样本、长文本、OOV、否定或转折样本，也可以点击混淆矩阵查看对应样本。

RNN/CNN 的“解释”会携带当时的权重和 Token 返回序列或卷积模块，不会重新随机初始化。NB/SVM 可以检查分类分数的来源。

NB、RNN、CNN 默认概率未经可靠性校准；SVM 的 margin 是决策分数，不是概率。“验证集校准 SVM”只使用独立验证样本，少量样本仍不能保证校准可靠。

#### 06｜损失与优化

用于观察学习率、初始参数和批大小如何影响真实梯度更新。

此模块使用两个自由参数的 Logistic 分类器，因此二维等高线对应的就是当前模型损失，不是高维模型的装饰图。

设置学习率、更新步数、批大小、初值和种子后，点击“运行真实训练”。可以选择慢收敛、稳步收敛和大步长震荡三个案例，再固定 A 做对照。

点击曲线或选择迭代点，可以检查当前参数、梯度和下一步参数。页面同时区分固定全数据评估损失与当步训练批次损失，两者不应混为一谈。

### 5. 数据集导入

“数据集管理”导入的是用于语料训练、预测和评测的样本，不是实验笔记。

支持 UTF-8 编码的：

- TXT：每个非空行一条文本，默认没有标签。
- CSV：第一行是字段名，可以调整分隔符和字段映射。
- JSONL：每行一个样本对象。
- JSON：样本数组，或包含 `samples` 数组的对象。

CSV 示例：

```csv
text,label,split,group
故事精彩，值得推荐,正向,train,a
体验糟糕，令人失望,负向,train,b
讲解清楚，内容有趣,正向,validation,c
功能复杂，使用麻烦,负向,validation,d
画面漂亮，音乐动听,正向,test,e
服务敷衍，态度很差,负向,test,f
```

字段含义：

- `text`：文本内容，必须提供。
- `label`：类别标签，可省略；当前分类工作台支持二分类。
- `split`：`train`、`validation` 或 `test`。
- `group`：将同模板或相关样本放在同一划分中，可省略。

操作顺序为：选择文件 → 映射字段 → 选择分词方式 → 校验预览 → 确认使用数据。

预览会显示样本数量、标签分布、Token 长度、重复情况和数据划分。未点击确认的候选文件不会成为当前数据集。

没有显式划分时，使用固定哈希按组划分，比例约为 70/10/20，小数据不保证精确比例。完全重复的 Token 序列或同组样本跨集合时会报错；近重复文本仍需要用户合理分组。

默认分词是中文按字符、英文按词；空格模式要求提前分词，不是自动中文词级分词器。

导入无标签数据可以训练词向量或进行预测，但不能得到 Accuracy/F1。分类训练需要适当的两类带标签训练样本。新数据与原模型的分词方式或类别顺序不兼容时，应明确重新训练，不会自动替换模型。

### 6. 实验笔记与导出

实验笔记用于保存“这一次实验怎样做、得到什么结果、观察到了什么”，不是单独的文本备忘录。

运行实验后点击“保存实验”，填写名称和备注。记录会包含输入、配置、随机种子、算法版本、数据来源、指纹和实际结果；神经模型实验还会保留适用的模型权重。

普通保存保留最近 20 条记录。记录优先保存到当前浏览器的本地存储；不可用或容量不足时退回内存会话，因此重要实验应主动导出。

模块顶部“导出”提供三种格式：

| 格式 | 用途 |
|---|---|
| 实验 JSON | 保存配置、输入和结果，用于重新计算 |
| 结果 CSV | 导出原始结果数值，用于表格分析 |
| 报告 Markdown | 整理参数和结果，作为报告材料 |

CSV 和 Markdown 不能代替 JSON 重放。

在“实验笔记”中选择实验 JSON，校验通过后点击“重新运行”。应用会恢复配置并重新执行计算，不会把文件里写的成绩直接当成已验证结果。导入记录应先重算，再在模块页面固定为 A。

当前只支持匹配的算法版本，不能保证跨版本完全一致。单个实验导入文件上限为 10 MiB。

多模型记录还可以导出“仅引用原数据”的 JSON，减少文件体积。重放前必须重新提供预处理和样本指纹匹配的原数据，仅有文件名相同不够。

注意：浏览器持久保存的是实验记录，并非整个工作环境。未保存的输入、导入数据和当前计算状态，不保证刷新后保留。

### 7. 跨模块使用流程

几个页面可以配合使用，而不必当作互不相关的展示：

```text
导入数据
  → 训练词向量
  → 将向量送入多模型工作台
  → 训练 RNN / CNN 并评测
  → 筛选错误样本
  → 返回同一模型内部解释
  → 保存笔记并导出
```

使用词向量快照时，工作台会显示维度、训练词表覆盖率和分词方式。分词不一致时，需要显式确认按 Token 交集重映射；未覆盖词使用固定种子初始化，之后 Embedding 仍可参与训练。

解释或修改权重后，可将同一 RNN/CNN 送回工作台评测。旧成绩不会自动代表新权重，需要重新运行。

### 8. 自动化测试有什么用

普通使用者无需运行测试。测试主要用于开发后检查计算和交互有没有被修改破坏。

- 单元测试：检查公式、梯度、注意力、卷积、序列模型、数据解析和指标是否正确。
- 浏览器测试：检查真实离线入口、Worker、点击交互、导入导出、A/B、笔记重放和响应式布局。
- 性能测试：测量特定规模下的计算耗时和交互表现，不证明分类准确率高。

测试源码在 `appendix/tests/`；测试结果、截图和性能证据在 `appendix/docs/evidence/`；HTML 浏览器报告在 `appendix/playwright-report/`。

已有验收在 WSL Chromium 中执行。Windows Chrome/Edge 的实际双击、断网运行仍需要人工验收，不能用 WSL 结果替代。

### 9. 使用边界

内置数据是 56 条原创、AI 辅助整理的教学句子，固定划分为 32 条训练、8 条验证、16 条测试。内置分类模型经过实际训练，但这些成绩不能代表真实场景的泛化能力。

各模块有明确输入预算：数据导入最多 50 MiB / 50,000 条；词向量最多 1,000,000 Token / 20,000 词 / 64 维；注意力最多 1024×1024；序列解释最多 256 Token；CNN、神经训练和四模型批量推理最多 128 Token。

这些是输入校验上限，不是所有规模均已通过性能验收的承诺。超限会拒绝，不会静默截断。建议先用小数据跑通，再逐步增加规模。实测结果和未测事项见 [验收记录](appendix/docs/acceptance.md)。

## 继续开发

从项目根目录执行：

```sh
npm --prefix tools run dev
npm --prefix tools run check
npm --prefix tools run test:run
npm --prefix tools run build:offline
npm --prefix tools run test:offline
```

开发入口通常为 http://localhost:5173，终端地址为准。开发配置位于tools，不能双击tools/index.html代替离线入口。

原有依赖已整体保存在tools/node_modules，版本与锁文件未升级，无需重新安装。新机器需要安装时执行 npm --prefix tools ci；开发网页需要Node，离线演示包不需要。

详细命令、数据格式和规模限制见 [工具说明](tools/README.md)。测试及课程材料见 [附录说明](appendix/README.md)、[验收记录](appendix/docs/acceptance.md)、[演示脚本](appendix/docs/demo-script.md)。

内置数据是56条原创、AI辅助整理教学句子，不是泛化基准；教学初始化与实际训练权重明确区分。Windows验收、更大规模拓展档、严格FPS和精确峰值内存仍有未测项，详见验收记录。
